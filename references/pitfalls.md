# 踩过的坑（照着避，别重新发现一遍）

乌兰布统那版从「点开能用」到「微信里也能用」，返工了十几轮。
下面按「会不会复发」分四类。**A 类模板已内建，别绕过；B/C 类每次都要人工核对。**

---

## A. 模板已经处理好的（别自己重造）

### A1. Leaflet 走 CDN → 微信里白屏
**症状**：电脑上正常，发到手机微信打开一片空白，地图区域什么都没有。
**原因**：`unpkg.com` 在微信内置浏览器里常被墙/超时；用户也可能在没网的地方。
**做法**：`assets/template.html` 里 Leaflet 的 CSS/JS 是**整份内联**的（约 158 KB）。
新做页面别改回 `<link href="https://unpkg...">`。验收项：产物里搜不到 `unpkg.com`。

### A2. `downloadKML()` 用 `<a download>` → 点了没反应
**症状**：按钮点下去，不下载、不报错、没有任何提示。
**原因**：微信内置浏览器、IDE 预览面板这类 webview 会**静默丢弃**下载。
**做法**：模板里的导出不是"直接下载"，而是弹一个三出口面板：
`保存为文件`（Blob，失败自动退 `data:` URI）→ `复制全部内容`（`clipboard` 失败退
`execCommand('copy')`）→ `关闭`。**状态行永远给文案**，不出现"点了没反应"这种状态。
另外 `<a>` 必须 `appendChild` 到 document 再 `click()`，否则部分浏览器忽略。

### A3. KML 里出现一条跨省直线
**症状**：某天的行车线在奥维里是一条几百公里的直线。
**原因**：备选日/无几何的 `routes` 为空，兜底逻辑把点位首尾相连。
**做法**：`noLine: true` 或 `routes` 为空时**不画线**；`build.py` 的 KML 生成已跳过空 geom。
验收项：产物里搜不到 `<LineString><coordinates></coordinates>`。

### A4. 高德瓦片上点位整体偏移几百米
**症状**：所有点都比实际位置偏一个固定方向。
**原因**：把 WGS-84 当 GCJ-02 用（或反过来）。
**做法**：见 `trip-schema.md` 第一节。`build.py` 会校验坐标是否落在国内合理范围，
但**它查不出 GCJ/WGS 混用**——这个只能靠取点时统一从高德/腾讯抄。

## B. 内容层面（每次都要核对，模板帮不了）

### B1. 「这个点顺不顺路」不能凭印象，要量
乌兰布统的灯笼河草原，最初被我判成"备选线，多绕 30 km"，塞进了备选日。
实测：它到主行车线的最近距离 **1.70 km**，高德算「城区→灯笼河」108.2 km，
沿现有几何累计 108.3 km —— **只差 0.1 km，根本就在路上**。

**做法**：把点位投影到已有行车线上，算「沿线路累计里程 vs 直接算路里程」，
差值 <3 km 就是顺路。别靠"地图上看着像绕"来决定。
（技能 `route-poi-on-path-check` 就是干这个的。）

### B2. 改一个里程数，会牵动十几处
改 D1 里程后，要同步：三天总里程、每张静态图上的标注、正文「约 XXX km」、
里程表、知识图谱、图例说明、KML。
**做法**：先 `grep` 全量列出旧数值的每一处，一次性替换完，再全量复查。
替换完必须**搜旧值，确认 0 处**——不是"我觉得都改了"。

### B3. 静态图和正文会脱节
图上印着「292 km」，正文改成了「289 km」，用户一眼就能看出来。
**做法**：图从数据重画，不要手改；重画后**打开图看一眼**（Read 图片），
别只看脚本输出 "OK"。

### B4. 点位不是越多越好
22 个点位 / 3 天，是"每个点位都有导航按钮"的量级。再加，手机上要滑半天，
而且每个点位的坐标都要准——多一个点，多一份出错概率。
**建议**：一天 4~7 个点；同日景点聚在一起；备选点单独放一个 `noLine` 日。

### B5. 时间线要能咬合
`07:50 早餐 → 08:25 出发 → 10:05 到休息点 → 10:25 出发 → 11:50 到午餐点`。
写完后把每天的时间加减一遍，别出现"10:05 到、09:50 出发"这种。

### B6. 坐标估的要标出来
盘龙峡谷的坐标至今是估值（OSRM 显示 74.9 km、路网未连通）。
**做法**：页面里明写「坐标是估值，出发前问民宿老板」，不要装作精确。

## C. 交付环境（决定了用户能不能真的打开）

### C1. 微信里 `.html` 是附件，没有「用浏览器打开」
**症状**：发给用户后，他点开只有"下载/其他应用打开"，没有浏览器选项，
页面打不开。
**原因**：微信对本地 HTML 附件的处理就是不给浏览器入口；部分版本能"用其他应用打开"，
但用户手机上不一定装了能解析的 App。
**做法**：**发布成在线链接**（`workbuddy_sites_deploy`），发链接而不是发文件。
链接在微信里点开是网页，不需要任何"打开方式"。
发布前确认页面**零外网依赖**（A1），否则微信里加载不出地图。

### C2. 微信 / QQ 内置浏览器调不起高德 App
**原因**：高德的 `callnative=1` 在微信/QQ webview 里被限制。
**做法**：页面里注明「微信里须先『在浏览器中打开』再点导航」。
这条提示别删——它是用户判断"是坏了还是被拦了"的唯一依据。

### C3. 手机高德 App 不能导入 KML
只能：电脑版高德「新功能 → KML/GPX 轨迹导入」（只画线不显示点）；
或电脑 `wia.amap.com` 批量导入（数据来源必须选**谷歌地图**，选高德会失败），
再在手机高德「我的 → 地图小程序」里看。
**做法**：别对用户说"导进高德就行"。说清楚：**最省事的是直接点气泡里的导航按钮**，
KML 是给奥维 / 两步路 / 高德网页版用的。

### C4. 手机高德途经点约 15 个上限
一天 5~7 个点没问题，三天合并成一条就会被截断。

## D. 工程习惯（这次吃过亏）

### D1. 同一文件的多处修改不要并行提交
一次消息里对**同一个文件**发多个编辑，只有最后一次落盘，其余静默丢失，
而工具照样报成功。**改完必须读回复核**，不要相信成功提示。

### D2. 生成器必须幂等
同样的数据跑两次，产物要**逐字节一致**（MD5 相同）。
否则你无法判断"这次 diff 是改对了还是生成器本身在抖"。
`build.py` 已做到：乌兰布统样例重跑与人工校验过的成品 **MD5 完全相同**。

### D3. 改完跑自检，别靠肉眼
```bash
python scripts/verify.py 产物.html --kml 产物.kml
```
它查的是这四类坑是否复发（内联、兜底面板、点位数、坐标范围、空折线）。

### D4. 老版本别覆盖
用户说"老的还留着"就是真的会对比。新产物换个文件名，老文件一个字都别动，
并在交付时说明老文件时间戳没变。
